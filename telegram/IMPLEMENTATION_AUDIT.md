## Operational boundaries and choices

- The initial smoke checks used isolated databases. The subsequent admin update applied migration 0005 to the local workspace SQLite database after a backup; production still requires the normal backed-up migration step. `run-backend.sh` already chooses `.venv312` when present and migrates before starting.
- Live bot token, hosted TBL execution, production connectivity and scheduler activation remain unverified until operator setup. Development TCP/443 connectivity was checked during implementation and is not proof of production access.
- Hosting quota differences between official pricing and documentation are recorded in the TBL README. Verify the actual account dashboard; no unlimited/ad-free promise is made.
- All optional commercial rules start inactive. Maintenance intervals and aftercare must be chosen/approved by staff. Existing completion timestamps are backfilled from the last recorded item update as a historical approximation.
- Enabling points applies the configured earning rule to eligible committed history. Any refund/cancellation reverses the original award in full. Review this policy before enabling.
- Coupon reservation is separate from redemption. Admin redemption requires finalized prices and no payment/completion; the existing financial engine remains authoritative. A redeemed coupon is not automatically reissued after a refund.
- Attribution defaults to seven days from the **first link visit**, configurable in admin; later visits cannot extend it. Only authenticated bookings by the intended customer are attributed; guest visits count without identity-based booking attribution.
- Ambiguous delivery can be lost rather than automatically resent; accepted API responses are not read receipts. No automatic paid broadcasts.

## Activation sequence

1. Use Python 3.12, install `backend/requirements.txt`, back up the intended database, and run `python manage.py migrate` from `backend`.
2. Configure HTTPS site/backend URLs, bot username, private bot token and a separate random integration secret in server configuration. Restart the backend. Keep sending disabled/dry-run until ready.
3. Follow `telebothost/README.md` to privately configure the same bot token, integration secret and backend URL; paste Logic into the specified commands with empty Answer fields. Publishing commands is an operator action.
4. Configure salon details and rules in `/admin/telegram`. Link the authorized manager's account and explicitly select report recipients. Leave customer campaigns unqueued for initial validation.
5. Run diagnostics on the actual production host. Install/adapt the timer and service. Enable dry-run linking/worker checks first, then perform an explicit staging/live test-to-self and verify callbacks/results before activating customer messaging.
6. Run `npx playwright test -c e2e/telegram.config.js` in a stable browser environment and retain the result with deployment checks. Enable desired commercial rules separately after reviewing dates, services, costs and eligibility.

See [setup and rollback](README.md) and [exact TBL installation](telebothost/README.md) for commands and contracts.
